# 11 — Language, copy and RTL

Three locales. Arabic is **first-class**, not a localisation layer applied afterwards.

| Locale | Register | Default in |
|---|---|---|
| `en` | Neutral English | — (secondary everywhere) |
| `ar-KW` | Gulf-neutral Arabic | Kuwait |
| `ar-EG` | Egyptian Arabic | Egypt |

**The two Arabic locales are authored separately.** Never machine-translate between them, and never treat `ar-EG` as a variant of `ar-KW` with substitutions. They are different registers written for different audiences, and the difference is the whole point.

Reference copy already written and approved lives in the design system at `guidelines/consumer-copy.card.html` — the high-traffic strings and the full push catalogue in all three registers. Port it into `copy/*.json`; do not rewrite it.

## 1. Voice rules — enforced, not advisory

**Never, about the food, in any language:** `leftover · expired · old · waste · scraps · بواقي · مخلفات · بايت`

The register is: **surplus · rescued · saved · available · فائض · أُنقذ · متاح**.

**Never as motivation:** guilt, charity framing, planetary shame. Nobody is doing anyone a favour — the price is good, the food is good, the rest is a bonus.

**Urgency is information.** "20 minutes left to collect" and "3 left" are facts. `Hurry! · Don't miss out! · Only for the fastest · اسرع! · لا تفوت الفرصة!` are banned and rejected at template review.

Implementation: a lint rule over `copy/*.json` in CI, with the banned list per locale in `copy/_forbidden.json`. A banned term fails the build. `app.ops_review_template` applies the same check server-side.

## 3. Numerals

A **user-facing setting** with a market default (`market_config.numerals_default`, `western` in both markets at launch). Every numeric component renders both.

```ts
formatNumber(n, { locale, numerals })   // 1750 → "1,750" | "١,٧٥٠"
formatMoney(m, locale, numerals)        // → "1.750 KWD" | "١٫٧٥٠ د.ك"
```

- Arabic decimal separator is `٫` (U+066B), thousands `٬` (U+066C) when Arabic-Indic is on.
- **Tabular figures always** for prices, countdowns and codes, so digits do not jitter as they tick.
- Order codes and provider references are **never** converted to Arabic-Indic. They are identifiers, and staff read them aloud against a printed or on-screen Latin string.

## 4. Bidi — three worked examples

Mixed-script strings are the most common source of visual bugs. Every Latin run and every numeric run inside Arabic text is wrapped in an **isolate**.

```tsx
// packages/i18n/src/bidi.ts
export const Iso = ({ children }: { children: ReactNode }) => (
  <Text style={{ writingDirection: 'ltr' }}>{'\u2068'}{children}{'\u2069'}</Text>
);  // FSI … PDI
```

| Case | Rendered | Why |
|---|---|---|
| Latin brand inside Arabic | `احجز بقشتك من ⁨Sadu Bakehouse⁩ قبل ٢٢:٠٠.` | Isolated, so the full stop stays at the right-hand end of the line |
| Price + currency | `السعر ⁨1.750 KWD⁩ بدلاً من ⁨6.000 KWD⁩.` | Number and currency are one isolated unit; the currency cannot flip sides |
| Code + time range | `رمزك ⁨4K7-92⁩ ووقت الاستلام ⁨21:00–22:00⁩.` | Hyphen and en dash stay inside their runs |

**Test:** snapshot every mixed-script string in both directions. A currency symbol on the wrong side of a number is a defect, not a rendering quirk.

## 5. RTL layout and icon mirroring

Full mirroring of layout, navigation, gestures, progress direction and iconography. Use logical properties everywhere: `marginStart`, `paddingEnd`, `insetInlineStart`. Never `left`/`right`.

| Always flips | Never flips |
|---|---|
| Back actions, chevrons, directional arrows | Clock faces, timers |
| Progress bars and step indicators | Media controls |
| Swipe-to-collect direction and its fill | The Bugsha kerchief mark |
| List disclosure indicators | Payment marks (KNET, Visa, Fawry) |
| Slider fills | Photographs |
| Map "recentre" affordance | QR codes |

Two flagship screens are **designed Arabic-first** as proof: browse (`S-C-020`) and redemption (`S-C-041`). Both exist as pinned Arabic frames in the consumer catalogue. Build them from the Arabic layout and mirror to English, not the reverse.

## 6. Truncation

Arabic **cannot be ellipsis-truncated mid-word** the way Latin can — Arabic script is connected, and cutting mid-word produces a shape that reads as a different letter.

| Locale | Rule |
|---|---|
| `en` | Character-level ellipsis permitted |
| `ar-*` | **Whole words only.** Truncate at the last complete word that fits, then `…` |

Store names are tested at **40 Latin / 30 Arabic** characters. Arabic line height is `×1.18` relative to Latin at the same nominal size — set in the design system tokens, not per component.

At the largest accessibility type size, components **reflow rather than truncate**. Price and pickup window may never be cut. The tab bar drops labels before it clips them. See the max-type frame in the consumer catalogue.

## 7. Dates, Hijri, weekdays

```ts
formatDate(d, { locale, market, calendar: 'gregorian' | 'both' })
```

- Gregorian is primary everywhere.
- **Hijri is shown as a secondary line during Ramadan** (`S-C-028`), and in store hours displays when the Ramadan schedule is active. Never primary.
- Weekend is **Friday–Saturday** in both markets; week starts Sunday. Weekday pickers order Sunday-first.
- Timezone abbreviation rendered whenever ambiguity is possible: `AST` (Kuwait, always), `EET` / `EEST` (Egypt, DST-dependent). Resolve from the instant, never hardcode.

## 8. Errors

`copy/errors.json` maps every `BGxxx` code to a message per locale. The server raises a **code and a key**; the client never displays a raw server string.

```json
{
  "BG110": { "en": "Someone got the last one", "ar-KW": "شخص آخر أخذ الأخيرة", "ar-EG": "حد خد الأخيرة" },
  "BG113": { "en": "{cap} is the most per person here", "ar-KW": "{cap} هو الحد لكل شخص", "ar-EG": "{cap} هو الحد للفرد" },
  "BG114": { "en": "You can't go below {sold} — that many are already paid for",
             "ar-KW": "لا يمكن النزول تحت {sold} — هذا العدد مدفوع بالفعل",
             "ar-EG": "مش هينفع تحت {sold} — العدد ده مدفوع خلاص" },
  "BG140": { "en": "We're checking your payment. Don't pay again.",
             "ar-KW": "نتحقق من دفعتك. لا تدفع مرة أخرى.",
             "ar-EG": "بنتأكد من الدفع. ما تدفعش تاني." }
}
```

Error copy states **what happened and what to do next**. Never a code, never "an error occurred".

## 9. Template review — enforced by schema

`notification_template` is keyed `(key, locale, version)` and carries `authored_by`, `reviewed_by`, `reviewed_at`, `published`, with a constraint that **a reviewer may not be the author**.

`app.publish_notification_template(key, version)` refuses unless **all three locales** of that version are reviewed. Publish stays disabled in the console until then — consumer-facing copy reaching tens of thousands of phones is not editable by one person acting alone.
